## 6.1 可视化模块设计目标

本文所实现的在线判题系统不仅需要完成代码提交、自动判题和结果返回等基础功能，还需要进一步将系统在运行过程中积累的数据转化为可被用户和管理员直接理解的信息。仅仅完成 Hive 与 Spark 的离线计算并不能充分体现大数据计算引擎在系统中的实际价值，只有将分析结果以图表、表格和指标卡片等方式进行可视化展示，才能真正形成“数据沉淀—离线计算—结果回流—页面应用”的完整闭环。因此，在系统设计中，前端分析页面并不是附属模块，而是系统数据价值落地的重要组成部分。

本系统中的可视化模块主要服务于两类对象：一类是普通用户，另一类是管理员。普通用户更加关注自身的做题状态、学习节奏和常见错误，因而页面重点是个人提交趋势、个人语言偏好、个人判题结果分布以及对已做题目的掌握情况；管理员则更关心平台整体运行状态、学生群体提交行为、题目质量与资源负载情况，因此页面重点是全站趋势、语言分布、结果分布、活跃时段、热门题目以及活跃用户。通过这种分角色设计，系统能够在同一套数据基础上，分别支撑学生自我反馈与平台管理决策。

从设计原则上看，本系统的可视化模块遵循以下三个目标。第一，展示内容要尽量与业务场景直接对应，避免出现虽然计算复杂但难以解释的图表。第二，图表之间要形成互补关系，例如既有单日分布图，也有多日趋势图，从而兼顾静态观察与动态观察。第三，页面中的图表应具有明确用途，不只是“展示数据”，还应能够帮助用户或管理员得出实际判断，例如是否出现学习懈怠、某类错误是否明显增多、某一时段是否存在系统负载高峰等。

在本章中，主要围绕两个核心分析页面展开：管理员侧的 `System Analytics` 页面和普通用户侧的 `My Analytics` 页面。由于论文篇幅和展示重点的限制，没有必要将页面中的所有图表逐一截图展示，因此更合理的写法是选择能够代表“趋势、分布、时段、结构和个体反馈”这几个核心维度的图表作为插图对象，而其他图表则通过正文进行说明与归纳分析。

## 6.2 管理员系统分析页面设计与应用价值

### 6.2.1 页面总体设计

管理员侧的 `System Analytics` 页面承担的是平台级观察与管理决策支撑功能。与普通用户页面不同，管理员页面不再聚焦单个用户的学习行为，而是从全局视角分析平台在某一时间段内的整体运行情况，包括提交规模、通过情况、语言使用结构、判题结果结构、活跃时段分布、热门题目和活跃用户等。该页面的设计目标，是让管理员能够在较短时间内把握平台运行状态，并根据分析结果进一步判断是否需要调整教学安排、优化题目内容或者对系统资源进行预留。

从页面结构上看，管理员分析页面由三层组成。第一层是顶部的概览指标，用于快速反映当天全站关键状态；第二层是趋势图和分布图，用于从时间与结构维度观察平台数据变化；第三层是热门题目、活跃用户和题目结果细分等明细型展示，用于帮助管理员进一步定位问题来源。这样的组织方式符合管理类页面“先总览、后分析、再定位”的阅读逻辑。

### 6.2.2 顶部概览指标的用途与意义

管理员页面顶部通常展示 `Daily Submissions`、`Daily Accepted`、`Daily AC Rate`、`Average Time`、`Average Memory` 和 `Active Users` 等指标。这些指标虽然不是复杂图表，但在管理页面中具有非常重要的作用。`Daily Submissions` 和 `Daily Accepted` 用于反映当天平台整体提交规模与通过数量，是最直接的活跃度指标；`Daily AC Rate` 则能够从整体上反映当天题目完成情况，帮助管理员快速判断学生整体做题状态是否正常；`Average Time` 和 `Average Memory` 能够从运行层面反映当天代码执行表现；`Active Users` 则从参与人数维度反映平台实际使用情况。

这些指标的意义在于，它们为管理员提供了一个“第一眼判断”。如果某天 `Daily Submissions` 显著降低，那么可能意味着学生使用频率下降，训练积极性减弱，或者课程安排导致当天练习不足；如果 `Daily Submissions` 很高但 `Daily AC Rate` 明显偏低，则可能说明当天题目整体较难，或者某些新增题目存在理解门槛较高的情况；如果平均运行时间和内存占用突然升高，则有可能反映出学生普遍开始提交更复杂题目，或者出现了需要进一步关注的性能问题。因而，这组指标虽然简单，却为后续图表分析提供了重要入口。

### 6.2.3 30-Day Trend 与 30-Day AC Rate 的用途与意义

`30-Day Trend` 图表主要展示最近一个月内平台每日提交数和每日通过数的变化趋势。该图的用途在于帮助管理员从时间维度观察平台热度是否稳定，以及学生整体参与状态是否发生变化。如果一个月内提交量整体呈下降趋势，则在一定程度上说明学生的使用积极性可能有所减弱；如果某些时间段提交量显著波动，则说明存在课程安排、实验任务集中、阶段性训练或考试节点等因素影响。与此同时，通过将提交数与通过数放在同一图表中进行比较，管理员还能够初步判断某些时间段是否存在“提交多但通过少”的异常现象，这通常意味着当时题目难度偏大、学生对相关知识点掌握不牢，或者训练内容突然变化导致适应成本上升。

与之配套的 `30-Day AC Rate` 图表则更直观地展示最近一个月内通过率的变化情况。与同时观察提交数和通过数相比，通过率折线更适合直接判断平台整体训练质量的变化。例如，若某几天的 AC Rate 持续偏低，则说明学生在这几天的整体完成效果不佳，管理员可以进一步回溯对应日期新增的题目内容、教学安排或训练主题，从而决定是否需要向任课教师反馈情况，帮助教师及时跟进学生状态。可以说，`30-Day Trend` 强调“数量变化”，而 `30-Day AC Rate` 更强调“完成质量变化”，两者结合之后，能够较完整地反映平台最近一个月的整体运行状态。

### 6.2.4 Language Distribution 与 30-Day Language Trend 的用途与意义

`Language Distribution` 图表用于展示某一天各编程语言的使用占比及对应通过率。该图表的用途在于帮助管理员观察学生在编程语言选择上的偏好结构，以及不同语言下的解题表现差异。若某种语言的使用人数明显偏少，可能意味着学生对该语言掌握不足，或在做算法题时缺乏信心，因此倾向于使用自己更熟悉的语言；若某种语言的使用率较高且 AC 率也较高，则说明学生在该语言上的熟练程度较好，能够较为稳定地完成题目。通过对不同日期的该图表进行横向比较，还可以进一步观察学生语言使用习惯是否随着课程推进而发生变化。

`30-Day Language Trend` 图表则从趋势角度展示一段时间内不同语言使用情况的变化。与单日的 `Language Distribution` 相比，该图能够更加直观地反映某种语言是否逐步被更多学生使用，或者是否出现明显下降。例如，若 Python 使用量持续增长，可能说明学生在完成中低难度题目时更倾向于选择开发效率较高的语言；若 C++ 仍然保持较高占比，则说明学生在算法训练中仍较依赖其标准库和性能优势。该图的意义在于，它能够辅助教学管理者判断学生群体在编程工具使用上的整体倾向，从而为课程安排、实验指导和语言教学重点提供参考。

### 6.2.5 Verdict Distribution 与 30-Day Verdict Trend 的用途与意义

`Verdict Distribution` 图表用于展示某一天平台判题结果的分布情况，包括 AC、WA、RE、CE、TLE 等。该图的主要用途是帮助管理员快速识别“当天学生最主要的问题是什么”。例如，如果某一天 `WA` 占比明显偏高，则说明学生主要问题在于算法逻辑、边界条件或输出格式处理不当；若 `CE` 占比较高，则可能意味着学生在语法、语言细节或环境使用方面仍不熟悉；若 `RE` 或 `TLE` 比例偏高，则可能说明学生在程序健壮性、时间复杂度或输入处理上存在问题。与单纯查看 AC 率相比，该图表可以更细粒度地定位错误类型，有利于管理员或教师在课后进行针对性跟进。

`30-Day Verdict Trend` 图表则将这种错误结构扩展到最近一段时间内进行观察。它的意义在于，可以让管理员更直观地看到学生群体在不同时间段内主要出现的是哪一类判题错误。例如，若最近一段时间 `CE` 持续较多，可能说明学生刚接触新的编程语言或开发环境；若 `TLE` 在某阶段明显增加，则可能意味着题目开始涉及更高复杂度算法，学生在时间复杂度控制上压力增大；若 `WA` 持续较高，则可能反映算法思路和边界处理方面存在普遍问题。相比单日的结果分布图，该趋势图更强调“变化”，更适合观察教学阶段性特征。

### 6.2.6 Hourly Activity 的用途与意义

`Hourly Activity` 图表用于展示某一天不同小时段内的提交量、通过量和活跃用户数。该图的用途主要体现在系统运行管理和资源预留两个方面。首先，通过该图可以观察某一天的访问高峰时段。例如，如果晚间某几个小时的提交量和活跃用户数显著升高，则说明该时段是学生集中练习和提交代码的高峰期。对于平台管理员而言，这类信息有助于判断未来同类型时段是否需要预留更多的系统资源，以避免在高峰时段出现评测排队、容器竞争或响应变慢的问题。

其次，小时活跃度图也能反映学生的学习习惯和训练节奏。若高峰主要集中在课后时间段，说明平台更多承担自主训练功能；若白天特定时间出现集中高峰，则往往与课程实验或教师统一布置任务有关。该图因此不仅是一个运维指标，也具备一定的教学行为观察意义。

### 6.2.7 Problem Verdict Breakdown 与 Top Problems 的用途与意义

`Problem Verdict Breakdown` 图表针对某一天最热门或指定题目，展示该题对应的判题结果细分情况。该图的用途在于帮助管理员将全站分析进一步聚焦到具体题目层面。若某道热门题的 `WA` 比例远高于其他结果，可能说明学生在算法思路或边界处理上普遍出错；若 `RE` 或 `TLE` 比例较高，则说明题目的实现难点更偏向程序鲁棒性或复杂度控制。管理员可以结合题目内容、测试数据和错误类型，对题目可能存在的问题进行判断，例如题目是否过难、题面是否表达不够清晰、是否需要增加提示或与教师沟通进一步干预。

`Top Problems` 表格则用于展示当天提交量最高的题目排行，并同时给出 AC 率、平均时间和平均内存等信息。其意义在于帮助管理员识别平台中真正被广泛使用、被反复练习或被普遍卡住的题目。一个题目如果提交量很高但 AC 率较低，说明它既受关注又有一定难度，是管理员重点关注的对象；如果提交量很高且 AC 率也较高，则说明该题具有较好的练习价值和适中的难度。通过这两种展示方式结合，管理员能够兼顾“题目热度”和“题目质量”两个维度。

### 6.2.8 Top Users 的用途与意义

`Top Users` 表格展示某一天提交量最高的用户及其通过率。该图表的用途主要是观察平台中最活跃的学生群体，并结合 AC 率判断其做题效果。对于管理员而言，这一信息可以帮助识别出哪些学生训练积极性较高，哪些学生在高提交量的同时仍保持较高通过率，说明其学习状态较好；若某些用户提交量很高但 AC 率偏低，则也可能意味着其正在高强度练习但掌握仍不稳定。虽然该图不直接用于评价学生优劣，但它能够为教师和管理员提供一个活跃度观察视角，有助于后续进行有针对性的教学关注。

### 6.2.9 管理员页面综合应用价值分析

总体来看，管理员侧 `System Analytics` 页面通过概览卡片、趋势图、分布图和明细表的组合，实现了从“平台整体状态”到“具体问题定位”的逐层分析。其综合价值主要体现在以下几个方面。第一，它能够帮助管理员判断平台活跃度与学生整体参与情况是否稳定；第二，它能够识别某一时间段学生常见错误类型，从而为教师调整教学节奏或课后讲解提供依据；第三，它能够揭示平台的高峰时段和潜在资源压力，为系统运维提供支持；第四，它能够帮助管理员观察题目热度与题目难点，提升题库管理质量。因此，管理员页面不仅是数据展示界面，更是在线判题系统向教学管理和平台运营延伸的重要体现。

## 6.3 普通用户个人分析页面设计与应用价值

### 6.3.1 页面总体设计

普通用户侧的 `My Analytics` 页面主要面向学生个人使用，目标是帮助用户通过数据回顾自己的做题过程、发现学习节奏变化并识别主要错误类型。相较于管理员页面强调“全局观察”，用户页面更强调“个体反馈”，其图表内容围绕个人提交行为展开，包括个人提交趋势、个人通过率变化、语言使用习惯、判题结果分布以及题目掌握情况等。\n\n从学习反馈角度看，单纯展示一次提交的判题结果只能告诉学生某一次代码是对还是错，而无法帮助其理解较长周期内的学习状态变化。通过将个人的历史提交数据组织成图表，用户可以看到自己在一段时间内的活跃程度、稳定程度和薄弱点，从而形成连续性的自我评估。这也是 `My Analytics` 页面存在的根本意义。

### 6.3.2 30-Day Submission Trend 与 30-Day AC Rate 的用途与意义

`30-Day Submission Trend` 图表展示用户最近一个月的每日提交数和每日通过数。它的用途在于帮助学生观察自己的学习节奏是否稳定。例如，若某些时间段几乎没有提交记录，则说明这些时间段练习较少，可能存在学习懈怠；若某些时间段提交数较多但 AC 数较少，则说明在这些时间段内虽然做题较积极，但完成效果不理想，可能反映出该阶段遇到的题目更难，或者学习状态不够稳定。相比只记忆“自己最近做了很多题”这种主观印象，趋势图可以用可量化的方式帮助学生进行更准确的回顾。

与此相对应的 `30-Day AC Rate` 图表则用更直观的方式展示个人通过率随时间变化的情况。其意义在于帮助学生从“质量”维度观察自己的学习状态。有时用户的提交数并不低，但 AC Rate 可能持续下降，这说明其近期虽然在练习，但解决问题的效率和准确性有所下降；反之，如果提交量稳定而通过率逐步提高，则说明学习效果正在改善。因此，这一图表能够作为学生自我反思的重要依据，帮助其及时调整学习节奏和题目选择策略。

### 6.3.3 Language Distribution 与 Daily Language Activity 的用途与意义

`Language Distribution` 图表用于展示用户在不同语言上的使用占比及通过率。它的用途在于帮助学生认识自己在语言选择上的习惯。例如，有些用户可能几乎总是使用某一种语言完成提交，这说明其对该语言更熟悉；若某些语言使用次数较少，则可能说明学生在这些语言上的掌握不够充分，或者在写算法题时缺乏自信。通过率信息则进一步反映了用户在不同语言上的解题表现，从而帮助其判断自己是否真正熟练掌握某门语言，而不是仅仅“偏好使用”某门语言。

`Daily Language Activity` 图表则从趋势角度展示用户在不同日期对各种语言的使用情况。与单一的语言占比图相比，这种趋势图更能体现用户语言使用习惯是否发生变化。例如，用户可能在某一阶段开始尝试更多地使用 Java 或 Python，这反映出其技能练习方向的变化。该图的意义在于帮助学生观察自己在语言能力培养方面是否更加均衡，同时也能够为其后续学习规划提供依据。

### 6.3.4 Verdict Distribution 与 Daily Verdict Activity 的用途与意义

`Verdict Distribution` 图表展示用户个人提交结果的总体分布情况。它的主要用途是帮助学生识别自己最常见的错误类型。如果 `WA` 占比较高，说明主要问题可能是算法思路或边界处理；若 `CE` 较多，则表明语法与语言细节掌握仍需加强；若 `RE` 或 `TLE` 较多，则说明程序鲁棒性、复杂度分析或输入处理存在不足。相比单次提交的错误反馈，这种分布图能够帮助学生从整体上认识自己的问题类型，更利于有针对性地提升能力。

`Daily Verdict Activity` 图表则展示不同日期下各类判题结果的变化情况。其意义在于帮助学生回顾“自己在哪些时间段错误特别多”，从而进一步判断当时是否是因为题目难度突然增加、学习状态不佳，或者缺少系统复盘。例如，若某几天 `WA` 显著上升，则说明当时的练习重点可能集中在逻辑较复杂的题目上；若某段时间 `CE` 增多，则说明语言使用存在生疏情况。通过这种时间化的错误回顾，学生能更清晰地认识自身问题是长期性的还是阶段性的。

### 6.3.5 Problem Stats 的用途与意义

`Problem Stats` 表格用于展示用户在已经做过的题目中的提交次数、通过次数和 AC 率等指标。与趋势图和分布图相比，这一部分更强调题目级别的掌握情况。其用途在于帮助学生查看自己在哪些题上提交较多、通过率较低，从而识别哪些题目自己真正掌握，哪些题目仍然处于“反复尝试但尚未稳定解决”的状态。对于学生而言，这种题目层面的统计有助于后续复习和查缺补漏，也能帮助其判断是否需要重新回顾某些知识点或典型题型。

从学习反馈意义上看，`Problem Stats` 是用户页面中最接近“学习成果记录”的模块。趋势图可以反映节奏，分布图可以反映结构，而题目统计表则直接反映具体训练对象的完成效果。因此，这一模块与前面的趋势和分布图共同构成了较完整的个人学习画像。

### 6.3.6 用户页面综合应用价值分析

综合来看，`My Analytics` 页面具有明显的学习反馈价值。第一，它帮助学生用数据方式回顾自己最近一段时间的学习节奏，识别何时积极、何时懈怠；第二，它帮助学生用结构化方式认识自己的错误分布，便于针对性改进；第三，它帮助学生观察自己在不同语言上的表现差异，从而更合理地规划语言学习；第四，它通过题目统计模块帮助学生识别未掌握或重复卡住的题目，增强后续复盘的针对性。换言之，用户页面将原本分散在历史提交中的信息进行了重新组织，使学生能够从“单次反馈”提升到“阶段性自我分析”。

本章围绕系统分析结果的可视化设计与应用价值展开讨论，重点分析了管理员侧 `System Analytics` 页面和普通用户侧 `My Analytics` 页面的设计思路、图表用途及其在实际场景中的意义。与传统仅提供基础查询功能的在线判题系统相比，本文所实现的系统通过引入多维统计图表和结构化数据展示，使离线分析结果真正转化为用户可感知、可理解、可使用的信息载体。
